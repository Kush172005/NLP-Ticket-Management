MILESTONE 1

Problem definition & business case

Define the support problem, intended users, scope and measures before building the classifier.

No model trained in M1
Problem

Manual intent tagging can be slow and inconsistent

Banking support agents read short messages and decide the issue category. Similar wording can refer to different intents, such as a pending transfer versus a failed transfer. The project aims to suggest a consistent intent for an agent to review.

Users

Who the tool is intended to help

  • Support agents: identify the ticket category quickly
  • Triage staff: use intent labels consistently
  • Support managers: understand issue distribution
  • Customers: possible downstream benefit to validate later

These are intended users; no bank interviews or customer pilot were conducted.

NLP task

One query → one of 77 intent labels

Supervised, single-label multiclass text classification for one English banking query. The prediction is an agent-facing category suggestion.

The model does not predict sentiment or urgency, generate replies, or take account actions. The application demonstrates routing and a ticket lifecycle using separate rules and human actions.

Feasibility

Possible with public labeled data and a laptop

  • Banking77: 10,003 train and 3,080 test examples
  • Normal laptop is enough; no GPU or paid API required
  • Fixed split seed and saved reports support reproducibility
  • Privacy and benchmark-to-bank domain shift remain risks

Data profile

Class balance and query length

  • Training class counts range from 30 to 160 examples
  • Largest-to-smallest class ratio: 5.33×
  • Training query length: mean 11.95, median 10 words
  • 95th percentile: 29 words

This imbalance is why macro F1 and per-intent recall matter.

Cleaning pipeline

Simple, explainable text preparation

  • Normalize Unicode and curly apostrophes
  • Mask URLs, email, card-like numbers, phone-like numbers and other numbers
  • Lowercase and expand common contractions; keep negation
  • Replace punctuation/non-English characters; collapse extra spaces

No stopword removal, stemming, lemmatization or truncation.

Excluded training rows

98 rows removed in a fixed order

  • 54 connected to official test duplicate groups
  • 42 repeated normalized training texts
  • 2 conflicting labels for normalized text

All official 3,080 test examples were retained.

Leakage and privacy

Grouped split checks, with limits documented

StratifiedGroupKFold used 7 folds, shuffle enabled, seed 42. Exact normalized matches were grouped. Longer messages were also grouped when word-trigram Jaccard similarity was at least 0.85. No exported split shared exact normalized text or a defined duplicate group.

Regex masking can miss names, addresses, account identifiers or unusual formats; it is not verified anonymization. There are no customer/thread IDs or timestamps to assess customer-level or temporal leakage. Banking77 is a public benchmark, not private bank traffic.

Accuracy = all correct predictions / all examples. Macro F1 averages F1 equally across intents. Weighted F1 gives larger classes more weight.

Baseline model

Word TF-IDF + Logistic Regression

TF-IDF gives useful words and two-word phrases more weight. Logistic Regression learns which word patterns are linked to each category.

Settings: word n-grams (1,2), min_df=2, sublinear TF, C=4, max_iter=1000.

Improved candidate

Word + character TF-IDF + Linear SVM

Word patterns capture meaningful terms and phrases. Character patterns can help with spelling and word-form clues. Linear SVM separates the 77 intents.

Settings: word n-grams (1,2); char_wb n-grams (3,5); min_df=2; character max features=300,000; C=1.0.

Monitoring plan

Operational checks

Check /ready, uptime, request/error totals, average latency and predicted-label counts. Logs include request ID, status and latency, not submitted text. Metrics reset when this prototype restarts.

The M5 guide proposes checking readiness every minute and alerting after two consecutive failures; review a 5-minute window for >5% server errors after at least 20 requests and p95 above 250 ms. These are starting thresholds for a future pilot, not guarantees.

Privacy, limits & next steps

Classroom-ready prototype, not public production

API stays on 127.0.0.1, has no login/rate limit/HTTPS, and stores aggregate metrics in memory. Successful predictions and their original ticket text are saved in a local SQLite database for review. Use sample data only. Browser session history also uses sessionStorage for the current tab.

Before production: security/privacy approval, authentication, rate limits, HTTPS, durable monitoring, representative bank data evaluation, and an agent pilot to measure correction rates and time saved.
